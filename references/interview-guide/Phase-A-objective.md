# Phase A — Objective: 목적·의사결정·청중

> **다루는 단계**: 9-step generic sequence 의 1·2 단계 (Objective + Stakeholder)
> **목표**: 리서치가 "무엇을 결정·설명하려는가" + "누가 답을 쓰는가" 를 먼저 잠금. 분류·메트릭·방법론은 일절 묻지 않음.

---

## 1. 핵심 질문 (사용자에게 묻는 순서)

### Q1. Decision-driving question
> **"이 리서치가 답해야 할 한 문장의 질문은 무엇입니까?"**

- 좋은 답: "TW·TH 디지털 광고 시장에서 LINE 의 FY26 진출 우선순위는 무엇인가?" (decision 명확)
- 나쁜 답: "TW·TH 디지털 광고 시장 조사" (topic 만 있고 question 없음)

만약 사용자가 topic 만 가지고 있다면 Q1.5 로 분기.

#### Q1.5. Topic → Question 좁히기 (필요 시)
> "그 토픽 안에서 답이 나오면 어떤 결정·설명이 가능해집니까? 그 결정을 지지하기 위한 가장 작은 질문은 무엇입니까?"

이건 외부 프레임워크의 *Craft of Research* (Booth/Colomb/Williams) 흐름:  
`topic → focused topic → question → so what? → research problem`

### Q2. Decision Use
> **"이 답이 나오면 누가, 언제, 어떻게 의사결정에 씁니까?"**

청중 + 사용 시점 + 사용 방식 모두 받아냅니다. 각각이 분리되면 더 좋습니다.

- 청중: CEO / 이사회 / 투자위원회 / 본인 / 클라이언트 / 학술 ...
- 시점: 즉시 / 다음 분기 / FY 시작 전 ...
- 사용 방식: 발표 / 보고서 / 의사결정 회의 / 자기 학습 ...

### Q3. Defensibility Bar
> **"답이 틀렸을 때 손실은 무엇입니까? 그 손실 크기에 비례해 검증을 어떻게 강화해야 합니까?"**

| 답변 강도 | Defensibility Bar |
|---|---|
| "내 학습용. 틀려도 저렴" | Low — single-source 허용 |
| "팀 의사결정 영향. 검증 필요" | Medium — Tier A/B 2 source cross-check |
| "CEO·이사회·투자자 제출. 모든 숫자 공격받음" | High — Tier S/A 100% + smell test 100% + dual sizing |

### Q4. Why Now
> **"왜 지금 이 답이 필요합니까? 1개월 후에 답해도 되는 질문입니까, 지금 풀어야 하는 질문입니까?"**

긴급도가 분명하면 Phase D 의 다음 sub-question 으로 넘어갑니다 ("품질 vs 속도" 트레이드오프). 긴급도가 모호하면 사용자에게 명확히 받아냅니다.

### Q5. Audience Constraints (선택)
> **"답을 받는 사람이 이미 알고 있는 것은 무엇입니까? 모르는 것은 무엇입니까? 받아들이지 않는 framing 은 무엇입니까?"**

청중의 사전 지식·언어·민감 영역을 미리 받으면 WRITER 단계에서 framing 을 잘 잡습니다 (예: 정치적으로 민감한 표현 회피).

## 3. Phase A 통과 체크 (Phase B 로 넘어가기 전)

다음 모두 충족해야 Phase B 시작:

- [ ] Q1 답이 **질문 형태** (topic 형태 아님)
- [ ] Q2 답에 청중 + 시점 + 사용 방식 **세 요소 모두** 명시
- [ ] Q3 답에 Defensibility 등급 명시
- [ ] 사용자가 "Phase A 승인" 명시 표현 (글자로)

## 4. 흔한 함정 (SCOPER 가 피해야 할 것)

| 함정 | 왜 문제 |
|---|---|
| 사용자가 "그냥 시장 조사" 라고 했다고 그대로 받아들임 | Q1.5 로 좁히지 않으면 ANALYST 가 모든 방향으로 자료를 모으게 됨 |
| 청중을 "내부 팀" 정도로 두고 넘어감 | Defensibility 와 framing 이 모두 약해짐. CEO·이사회·투자자 여부는 반드시 확인 |
| Defensibility 를 사용자가 묻지 않으면 Medium 디폴트로 잠금 | 잘못된 디폴트. 사용자에게 명시적으로 묻고 답을 기록 |
| Why Now 를 안 묻고 "품질 우선" 디폴트 | 일정 압력이 숨겨지면 Multi-Session 협상이 늦어짐 |

## 5. 외부 프레임워크 매핑 (참고)

| 외부 프레임워크 | 본 Phase A 와 매핑 |
|---|---|
| Heilmeier Catechism | "Who cares? / What is new? / How is it done today?" 가 Q2·Q3 와 직결 |
| Decision-Centered (Bain 식) | Q2 의 "decision use" 가 핵심. 이 스타일 (S2) 를 선택할 가능성 시그널 |
| Question-Refinement (Craft of Research) | Q1.5 가 직접 차용 |
| Engagement-Letter | Q4 + Q3 가 contractual scope 의 입력값 |
